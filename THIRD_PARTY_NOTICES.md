## 3) External comparison models (not vendored)

The three baselines under `comparison_models/` are **referenced, not vendored**.
Their upstream sources are cloned into the Git-ignored
`.external_pose_sources/` directory at exact pinned revisions and are never
modified in place. No upstream source file, weight or generated export from
these projects is committed.

| Model | Upstream repository | Pinned revision | License |
|---|---|---|---|
| RTMPose-M | https://github.com/open-mmlab/mmpose | `759b39c13fea6ba094afc1fa932f51dc1b11cbf9` | Apache-2.0 |
| ViTPose-B | https://github.com/ViTAE-Transformer/ViTPose | `c050ed29112da7704797cc1a65af0234b525010d` | MIT |
| PoseBH-B (single-dataset adaptation) | https://github.com/uyoung-jeong/PoseBH | `8f03438f913b559edb0a2beed54e77d1560edba3` | see upstream `LICENSE` |

Scope of our own code: `comparison_models/` contains original adapters,
dataset/protocol code and configuration written for this work. They import the
upstream packages at runtime rather than copying them.

RTMPose additionally uses an import-only overlay generated by
`comparison_models/rtmpose/make_overlay.py` into
`.external_pose_sources/rtmpose_birdgaze_overlay/`. It patches **only** the
unrelated `RTMOHead` registration so that MMPose can be imported without an
incompatible MMDetection. The overlay records SHA-256 manifests and the
generator verifies that the pinned upstream checkout is byte-unmodified
(`git show <pin>:<path>`), so no upstream architecture file is altered.

Attribution obligations:

- Cite the original RTMPose, ViTPose and PoseBH papers when reporting results.
- Keep upstream copyright and license notices intact in any redistributed copy.
- Label PoseBH results as **PoseBH-B (single-dataset adaptation)**; the
  published multi-dataset pretrained method and its CPS/CSS results are not
  reproduced here.
